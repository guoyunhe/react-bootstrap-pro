# Nav

`Nav`, `NavItem`, and `NavLink` provide navigation markup with optional tabs,
pills, and underline styles. They do not switch tab panels themselves.

## Overflow

`NavOverflow` provides markup for Bootstrap's Priority+ plugin. The plugin
measures the wrapper and hides items that do not fit, cloning their links into
a More menu. It observes container size with `ResizeObserver`, falling back to
window resize events when unavailable. The generated menu uses Bootstrap's
JavaScript Menu plugin, not this library's React `Menu`.

The examples initialize the Bootstrap plugin after mounting and dispose it on
unmount using [this helper](./use-nav-overflow.ts). `data-bs-toggle` alone only
enables Bootstrap's data API when the plugin is loaded and its `DOMContentLoaded`
handler sees the wrapper; React content mounted later needs explicit
initialization. Bootstrap's default CSS hides an uninitialized nav, so without
JavaScript there is no usable navigation or overflow menu unless the application
provides a fallback (for example, render a plain `Nav` without `NavOverflow`).

The plugin clones DOM nodes, not React handlers or component state. Use normal
links for overflowed items; do not rely on React event handlers on the clones.
Avoid dynamically changing the list without managing the plugin instance and
its lifecycle. Bootstrap's menu relocation assumes its own menu markup and is
not interchangeable with a React-controlled `Menu`.

## Accessibility

Wrap list navigation in a named `nav` landmark when appropriate; do not put
`role='navigation'` on the list itself. An active link defaults to
`aria-current='page'`, which can be overridden. Navigation styled as tabs is
not a tab interface: do not add tab roles unless implementing the full tab
interaction pattern.

`disabled` supplies styling, `aria-disabled`, and `tabIndex={-1}`, but does
not prevent activation of an anchor with `href` or set the native `disabled`
attribute on a button. Remove the destination or implement appropriate
activation prevention. For buttons, use a native button or a custom component
that sets its native `disabled` attribute: `NavLink` consumes its own
`disabled` prop rather than forwarding it.

## API

All components accept native props for their selected element and
[`Box`](../box/README.mdx#api) utility props through `BoxProps<C>`;
`component` changes the default element.

### Nav

Renders `ul` by default. Its own props are:

| Prop          | Type                               | Description                                           |
| ------------- | ---------------------------------- | ----------------------------------------------------- |
| `variant`     | `'tabs' \| 'pills' \| 'underline'` | Navigation style.                                     |
| `orientation` | `'horizontal' \| 'vertical'`       | `vertical` adds the vertical modifier only for pills. |
| `fill`        | `boolean`                          | Distributes space proportionally.                     |
| `justified`   | `boolean`                          | Gives items equal width.                              |

### NavItem

Renders `li` by default and has no own props.

### NavLink

Renders `a` by default. Its own props are `active?: boolean` and
`disabled?: boolean`; see the accessibility notes for their behavior.

### NavOverflow

Renders `div` by default and has no own props. It defaults
`data-bs-toggle` to `nav-overflow`; this does not initialize the plugin itself.

### NavOverflowItem

Renders `li` by default and has no own props. Adds `nav-overflow-item` for
custom Bootstrap overflow markup; use `component={NavItem}` when a `nav-item`
class is also needed.

### NavOverflowIcon

Renders `span` by default and has no own props. Adds `nav-overflow-icon` and
defaults `aria-hidden` to `true`.
