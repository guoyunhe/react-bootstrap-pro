# Toast

`Toast` renders a lightweight notification with `.toast`, together with
`ToastContainer`, `ToastHeader`, and `ToastBody` for the surrounding layout.
Toasts are hidden until `show` is set, so React controls their visibility; the
components do not load Bootstrap JavaScript. A toast defaults to a live region
with `role='alert'`, `aria-live='assertive'`, and `aria-atomic='true'`.

## API

### Toast

Renders a `div` with `.toast`. Its own props are `show`, `instant`, and
`translucent`; it inherits native props for the selected element and all
[`Box`](../box/README.mdx#api) utility props through `BoxProps<C>`. Without
`show`, the toast stays hidden.

| Prop          | Type      | Description                                                   |
| ------------- | --------- | ------------------------------------------------------------- |
| `show`        | `boolean` | Adds `.show` to reveal the toast.                             |
| `instant`     | `boolean` | Adds `.toast-instant` and removes the fade transition.        |
| `translucent` | `boolean` | Adds `.toast-translucent` with a blurred, saturated backdrop. |

The toast defaults to `role='alert'`, `aria-live='assertive'`, and
`aria-atomic='true'`; pass these props to choose different values.

### ToastContainer

Renders a `div` with `.toast-container`, which spaces stacked toasts vertically.
It has no own props and defaults to `role='region'` and `aria-live='polite'`.
Position it with props such as `position`, `top`, `end`, and `p`, and it inherits
native props and all [`Box`](../box/README.mdx#api) utility props through
`BoxProps<C>`.

### ToastHeader

Renders a `div` with `.toast-header`, a flex row. It has no own props and
inherits native props and all
[`Box`](../box/README.mdx#api) utility props through `BoxProps<C>`.

### ToastBody

Renders a `div` with `.toast-body`. It has no own props and inherits native props
and all [`Box`](../box/README.mdx#api) utility props through `BoxProps<C>`.

## Accessibility

Wrap toasts in a live region so screen readers announce them without moving
focus. `ToastContainer` provides `role='region'` and `aria-live='polite'` by
default, and `Toast` sets `aria-atomic='true'` so the whole message is announced
as one unit.

Choose the role and politeness to match the message: keep `role='alert'` with
`aria-live='assertive'` for important updates, and use `role='status'` with
`aria-live='polite'` for routine ones. Use an [`Alert`](../alert/README.mdx)
instead when the information is essential to the task, such as a list of form
errors.

Keep the live region mounted before the toast appears; creating the region and
its content at the same time is often not announced. If you hide toasts with a
timer, leave enough time to read the message. Without a timer, always provide a
close button, and avoid focusable controls inside auto-hiding toasts because
toasts do not receive focus.
