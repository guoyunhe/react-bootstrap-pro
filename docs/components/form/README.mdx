# Form

Bootstrap's form controls extend the rebooted form styles with component
classes. `FormField`, `FormLabel`, and `FormText` build a control with its label
and help text; [`Input`](../input/README.mdx), [`Select`](../select/README.mdx),
and [`Textarea`](../textarea/README.mdx) wrap their respective native elements.
`Checkbox`, `Radio`, `Switch`, and `Range` render the `.check` checkbox, `.radio`
radio, `.switch` track, and `.form-range` slider. `InputGroup` attaches add-ons
to a control, `FormFloating` wraps a control and label into a floating-label
field, and `FormControl` can wrap a ghost `Input` with adornments. Always set an
appropriate `type` on inputs so browsers provide the
matching keyboard, validation, and autofill behavior.

## Disabled forms

Add the native `disabled` attribute to a single control, or disable a group of
controls with a `fieldset disabled`. Browsers ignore all native form controls
inside a disabled fieldset, including keyboard and mouse interaction.

the group.

## Floating labels

`FormFloating` wraps a label and a control to build a floating label. Put the
label first and bind it to the control with `htmlFor`. Textual controls need a
non-empty `placeholder`: the CSS-only implementation uses `:placeholder-shown`
to detect an empty field. The placeholder stays transparent until the control
is focused.

## Form adorn

Wrap a ghost `Input` in a `FormControl component='label' adorn`. This lays out
adornments beside the input, and clicking the icon, text, or padding focuses
the control without JavaScript. Use `adornEnd` instead of `adorn` to place the
adornment on the trailing side.

## Layout

Forms stack vertically by default, because Bootstrap applies `display: block`
and `width: 100%` to almost every form control. Spacing utilities, the grid, and
flex utilities change that per form. Wrap each group of fields in a `<form>`,
and set `type` on every button, because a `<button>` inside a form defaults to
`type="submit"`.

### Utilities

Margin utilities are the easiest way to add structure: group each label,
control, and help text in a `FormField` and give the group a bottom margin. Stick
to one direction throughout the form for consistency.

## Validation

Provide actionable feedback with Bootstrap's form validation styles. `Form`
manages the `data-bs-validate` opt-in and `aria-invalid`, `FormFeedback`
renders feedback, and controls accept `validation` for server-side states.

### How it works

- **Client-side validation** uses CSS pseudo-classes scoped behind
  `data-bs-validate`. Set `validation` on `Form` to opt in to `:user-invalid`
  styling, which appears after the user interacts with a control.
- By default, **only invalid styling is shown**. Set `validation='valid'` to
  also style valid fields.
- **Server-side validation** uses `validation` on controls to render
  `.is-valid` or `.is-invalid` without requiring user interaction.
- `FormFeedback` renders `.invalid-feedback`, `.valid-feedback`, or their
  tooltip variants.
- When `validation` is set, `Form` defaults to `noValidate`, checks validity
  on submit, and updates `aria-invalid` as the user corrects marked controls.

### Custom styles

Set `validation` on `Form` and give each `FormFeedback` an `id` so the control
can reference it through `aria-describedby`. Add `required` to each required
field and provide field-specific messages.

`Form` calls `checkValidity()` on submit, marks eligible controls with
`aria-invalid`, and prevents submission while any field is invalid.

### Server-side

Indicate valid and invalid fields returned by the server with the control's
`validation` prop. Render both feedback messages and let the state determine
which one is visible.

  <ValidationServerSideDemo />
</DemoContainer>

outside the `.form-floating` wrapper.

### Supported elements

`FormControl`, `Input`, `Textarea`, `Select`, `Checkbox`, `Radio`, `SwitchInput`, `Range`,
`ChipInput`, `Combobox`, and `OtpInput` accept
`validation='valid' | 'invalid'`. For an adorned input, set `validation` on
`FormControl` to style its wrapper; input groups and floating labels can use
their inner control's state.

## Accessibility

Give every control an accessible name. The simplest approach is a visible
`FormLabel` bound with `htmlFor`, or `aria-label` when no visible label is
possible. Associate help text with `aria-describedby`. A floating label's
placeholder is not an accessible name, so keep its visible label.

Associate feedback with its control through `aria-describedby`. When
`validation` is set, `Form` sets `aria-invalid` on eligible controls on submit
and keeps marked controls in sync as the user corrects them. Use `aria-live` or
a status element for messages appearing without a focus change, and make
labels and feedback specific to each field.

## API

### FormControl

Renders a `div` by default.

| Prop         | Type                   | Description                                                       |
| ------------ | ---------------------- | ----------------------------------------------------------------- |
| `adorn`      | `boolean`              | Adds `.form-adorn` to arrange adornments and a ghost input.       |
| `adornEnd`   | `boolean`              | Adds `.form-adorn` and places the adornment on the trailing side. |
| `size`       | `'sm' \| 'lg'`         | Applies the small or large form-control size to the wrapper.      |
| `validation` | `'valid' \| 'invalid'` | Applies the matching validation class to the wrapper.             |

Inherits native props for the selected element and
[`Box`](../box/README.mdx#api) utility props, including `component` to select
the element. Use `component='label'` for a ghost input inside the wrapper.

### FormAdornIcon

Renders a `div` by default and adds `.form-adorn-icon`. It has no additional
props. Inherits native props for the selected element and
[`Box`](../box/README.mdx#api) utility props, including `component` to select
the element. Use `aria-hidden='true'` for decorative icons.

### FormAdornText

Renders a `span` by default and adds `.form-adorn-text`. It has no additional
props. Inherits native props for the selected element and
[`Box`](../box/README.mdx#api) utility props, including `component` to select
the element. Use `aria-hidden='true'` for decorative text.

### Form

Renders a `form` by default.

| Prop         | Type                                | Description                                                                                         |
| ------------ | ----------------------------------- | --------------------------------------------------------------------------------------------------- |
| `validation` | `boolean \| 'valid'`                | Enables validation handling; `true` adds `data-bs-validate` and `'valid'` also styles valid fields. |
| `onSubmit`   | `FormEventHandler<HTMLFormElement>` | Called after validation; `event.defaultPrevented` is set when invalid.                              |
| `onInput`    | `FormEventHandler<HTMLFormElement>` | Called alongside the internal `aria-invalid` update.                                                |

Inherits native form props and [`Box`](../box/README.mdx#api) utility props.
The native `noValidate` prop defaults to `true` when `validation` is supplied.
Passing `validation={false}` still enables the submit check and defaults
`noValidate` to `true`, but does not add `data-bs-validate`.

### FormFeedback

Renders a `div` by default.

| Prop      | Type                   | Description                                                 |
| --------- | ---------------------- | ----------------------------------------------------------- |
| `type`    | `'valid' \| 'invalid'` | Renders valid or invalid feedback; defaults to `'invalid'`. |
| `tooltip` | `boolean`              | Renders a validation tooltip instead of inline feedback.    |

Inherits native `div` props and [`Box`](../box/README.mdx#api) utility props,
including `id` for `aria-describedby`. Its inherited `component` prop is typed
as `'div'`.

### FormFloating

Renders a `div` by default.

| Prop     | Type      | Description                                          |
| -------- | --------- | ---------------------------------------------------- |
| `always` | `boolean` | Keeps the label floated and the placeholder visible. |

Inherits native props for the selected element and
[`Box`](../box/README.mdx#api) utility props, including `component` to select
the element.

### FormField

Renders a `div` by default and has no additional props. Inherits native props
for the selected element and [`Box`](../box/README.mdx#api) utility props,
including `component` to select the element.

### FormFieldContent

Renders a `div` by default and has no additional props. Inherits native props
for the selected element and [`Box`](../box/README.mdx#api) utility props,
including `component` to select the element.

### FormLabel

Renders a `label` by default.

| Prop  | Type                      | Description                                                                               |
| ----- | ------------------------- | ----------------------------------------------------------------------------------------- |
| `col` | `boolean \| 'sm' \| 'lg'` | Renders `.col-form-label` for horizontal forms; `'sm'` and `'lg'` match the control size. |

Inherits native props for the selected element and
[`Box`](../box/README.mdx#api) utility props, including `component` to select
the element.

### FormText

Renders a `div` by default and has no additional props. Inherits native props
for the selected element and [`Box`](../box/README.mdx#api) utility props,
including `component`; use `span` for inline help text.
