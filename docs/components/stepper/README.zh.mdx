# Stepper 步骤条

`Stepper` 使用 CSS Grid 渲染有序的步骤列表。步骤序号来自 CSS 计数器，并通过连接线
相连，因此序号始终与实际渲染的条目一致。为已完成和当前步骤设置 `active`；横向空间
足够时，可使用响应式的 `horizontal` 选项。

## 响应式

将 `horizontal` 设为断点（如 `'sm'`），即可仅在查询容器足够宽时切换为横向布局。这些
断点基于容器查询，因此需要把步骤条放入容器查询容器中，例如设置
`containerQuery='inline'` 的 `Box`。

## API

### Stepper

默认渲染为 `ol`，可使用 `component` 更换元素。自有属性为 `horizontal` 和
`overflow`；继承所选元素的原生属性，以及通过 `BoxProps<C>` 继承的全部
[`Box`](../box/README.zh.mdx#api) 工具类属性。

| 组件属性     | 类型                                               | 说明                                           |
| ------------ | -------------------------------------------------- | ---------------------------------------------- |
| `horizontal` | `boolean \| 'sm' \| 'md' \| 'lg' \| 'xl' \| '2xl'` | 使用横向布局；设置断点时改为基于容器查询生效。 |
| `overflow`   | `boolean`                                          | 为较长的横向步骤序列启用行内滚动。             |

`horizontal` 添加 `.stepper-horizontal`。设置断点时则改为添加对应的
`{breakpoint}:stepper-horizontal` 类，在该容器断点及以上生效。`overflow` 会在列表外
包裹一层 `.stepper-overflow` 容器，使其沿行内轴滚动，并作为行内尺寸查询容器，让断点值
能够响应可用宽度。

### StepperItem

默认渲染为 `li`，可使用 `component` 更换元素。自有属性为 `active?: boolean`，会添加
`.active` 并将 `aria-current` 默认设为 `step`。继承所选元素的原生属性，以及通过
`BoxProps<C>` 继承的全部 [`Box`](../box/README.zh.mdx#api) 工具类属性，因此可用
`component='a'` 或 `component='button'` 生成可交互的步骤。

| 组件属性 | 类型      | 说明                           |
| -------- | --------- | ------------------------------ |
| `active` | `boolean` | 将步骤标记为已完成或当前步骤。 |

## 无障碍访问

有序列表本身已表达步骤顺序，因此请保持有意义的源码顺序。已完成的步骤同样需要设置
`active`，但只应在当前步骤上保留 `aria-current='step'`：为其他激活步骤传入
`aria-current='false'`，让辅助技术只识别出一个当前步骤。

步骤默认是静态文本；若渲染为链接或按钮，则保持其原生键盘行为。当链接步骤条的用途不够
明确时，请通过 `aria-label` 等属性提供可访问名称，并让步骤标签简短且彼此不同。
