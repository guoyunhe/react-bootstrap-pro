# Stepper

`Stepper` renders an ordered list of steps with CSS Grid. Steps are numbered by a
CSS counter and joined by tracks, so the counter always matches the rendered
items. Set `active` on completed and current steps, and add the responsive
`horizontal` option when there is enough inline space.

## Responsive

Set `horizontal` to a breakpoint such as `'sm'` to switch to the horizontal
layout only when the query container is wide enough. These breakpoints use
container queries, so wrap the stepper in a container query container, for
example a `Box` with `containerQuery='inline'`.

## API

### Stepper

Renders an `ol` by default; use `component` to change the element. Its own
props are `horizontal` and `overflow`. It inherits native props for the selected
element and all [`Box`](../box/README.mdx#api) utility props through
`BoxProps<C>`.

| Prop         | Type                                               | Description                                                                 |
| ------------ | -------------------------------------------------- | --------------------------------------------------------------------------- |
| `horizontal` | `boolean \| 'sm' \| 'md' \| 'lg' \| 'xl' \| '2xl'` | Uses the horizontal layout; a breakpoint restricts it to container queries. |
| `overflow`   | `boolean`                                          | Enables inline scrolling for long horizontal step sequences.                |

`horizontal` adds `.stepper-horizontal`. A breakpoint value adds the matching
`{breakpoint}:stepper-horizontal` class instead, which applies from that
container breakpoint up. `overflow` wraps the list in a `.stepper-overflow`
container that scrolls along the inline axis and acts as an inline-size query
container, so a breakpoint value can respond to the available width.

### StepperItem

Renders an `li` by default; use `component` to change the element. Its own prop
is `active?: boolean`, which adds `.active` and defaults `aria-current` to
`step`. It inherits native props for the selected element and all
[`Box`](../box/README.mdx#api) utility props through `BoxProps<C>`, so
`component='a'` or `component='button'` produce interactive steps.

| Prop     | Type      | Description                             |
| -------- | --------- | --------------------------------------- |
| `active` | `boolean` | Marks the step as completed or current. |

## Accessibility

The ordered list conveys the sequence, so keep the source order meaningful. Mark
completed steps with `active` too, but keep `aria-current='step'` on the current
step only: pass `aria-current='false'` to the other active steps so assistive
technology exposes a single current step.

Steps are static text unless they render as links or buttons, which keep their
native keyboard behavior. Give a link stepper an accessible name, such as
`aria-label`, when its purpose is not clear from context, and keep step labels
short and unique.
