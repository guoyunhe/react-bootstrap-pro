# Switch

`Switch` renders the `.switch` track and indicator with a native checkbox input
layered over it. The input keeps native checkbox semantics and sets
`type='checkbox'`, `role='switch'`, and the `switch` attribute, which browsers
that support it can use for haptic feedback. Wrap the switch in a `FormField` and
bind a `<label>` through `htmlFor` to place the label next to the control.

## Custom width

Set `width` and `indicatorWidth` on `Switch` to build a wider switch. Numbers are
treated as pixels; strings pass through. The props write the
`--bs-switch-width` and `--bs-switch-indicator-width` custom properties on the
track.

## API

### Switch

Renders a `div` track by default with an inner `<input type='checkbox'>` that
always has `role='switch'` and the `switch` attribute.

| Prop             | Type                     | Description                                   |
| ---------------- | ------------------------ | --------------------------------------------- |
| `size`           | `'sm' \| 'lg'`           | Scales the track and its label.               |
| `validation`     | `'valid' \| 'invalid'`   | Adds the validation class to the inner input. |
| `width`          | `CSSProperties['width']` | Sets the track width.                         |
| `indicatorWidth` | `CSSProperties['width']` | Sets the indicator width.                     |
| `inputRef`       | `Ref<HTMLInputElement>`  | Ref to the inner checkbox.                    |

Its own props are `size`, `validation`, `width`, `indicatorWidth`, and
`inputRef`. Native checkbox props are forwarded to the inner input, including
`id`, `name`, `value`, `checked`, `defaultChecked`, `disabled`, `required`,
`readOnly`, `autoComplete`, `form`, `onChange`, `onInput`, `onBlur`, `onFocus`,
and the `aria-label`, `aria-describedby`, and `aria-labelledby` attributes. The
remaining native props and all [`Box`](../box/README.mdx#api) utility props apply
to the track; `theme`, `style`, and `component` target the track as well.

## Accessibility

The inner input always renders `role='switch'`, so assistive technologies
announce the control as a switch instead of a checkbox and expose its native
checked state. Give it an accessible name with a `<label>` bound through
`htmlFor`, or with `aria-label`. Keyboard interaction stays native: Space
toggles the switch when the input has focus.

Group the label with the track in a `FormField`, as in the examples, so the grid
layout places them side by side and the label follows the disabled styling. Color
is only a visual cue; keep a visible label and do not rely on the checked color
alone to communicate state.
